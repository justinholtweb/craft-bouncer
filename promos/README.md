# Plugin Store promo images

Marketing images for the Bouncer listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-bouncer](https://justinholt.com/plugins/craft-bouncer).

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `bouncer-promo-N.png`, 1920×1080 (rendered at 2× in headless Chrome, then
downsampled so the type stays crisp).

## The cover badge quotes the price

`Lite free · Pro $59` — the same form Bird and Bandage use. **A pricing change has to reach four
places:** this badge, the marketing site (`_partials/hero.twig`, `_partials/cta-banner.twig`,
`_partials/pricing.twig`, the FAQ, `_layouts/base.twig`'s schema.org offers, and
`docs/editions.twig`), the repo's `README.md`, and the edition prices at `id.craftcms.com`.

The renewal figure — $29/year — is deliberately **not** on the slide. The badge has room for one
number, and the Plugin Store shows the renewal next to the price anyway; two figures at 22px on a
1920×1080 slide read as a pricing table nobody asked for.

## Notes

`assets/icon.svg` is **not** a straight copy of `../src/icon.svg`. Two edits are applied, and both
have to be reapplied whenever the icon changes:

- **The white frame path (`p0`) is removed.** The icon is a traced SVG, and `p0` is a full-canvas
  rectangle with the rounded plate as its second subpath — filled white, it paints everything
  *outside* the tile. On a light page that is invisible; on these slides it is a white box around
  the icon, which is exactly how the first render came out.
- **The viewBox is cropped to the tile** (`23.5 22.5 237.2 236.2`), so the mark fills its 460px box
  the way the rest of the family's icons do instead of floating in transparent padding.

`assets/watermark.svg` is `../src/icon-mask.svg` with the fill switched to white. **Three files, one
geometry** — change the icon and change all three.

**The watermark needed two corrections, both because this mark is a dense filled silhouette.**
Filled rather than stroked is right here: the mark is already a silhouette, and outlining it would
trace the gap between every muscle and read as noise. But mass is exactly what a watermark cannot
have. At the family's usual 1150px / `left: -8%` the figure sat behind the headline column and read
as a grey man standing on every slide; Bird's crop — 980px at `left: -20%` — pushes him off the
edge so only a shoulder and the rope carry. And **0.022**, already the reduced opacity the family
uses for filled marks, was still too strong: this deck runs **0.016**.

Two layout rules inherited from the rest of the family, both of which bit again:

- **One line per bullet, about 55 characters at 25px.** The copy column is 780px inside a 130px
  gutter and the panel starts at `left: 900px`, so a bullet that wraps runs at the panel and lands
  on top of it — nothing clips, the text simply overlaps.
- **`.points li` is a flex container.** An inline `<span class="mono">` left loose in the text
  becomes a *sibling flex item* and picks up the 16px gap on both sides. Every point keeps its text
  in one `<span class="t">`.

Severity on slide 6 is carried by **colour**, never by a border style — a dashed 1px border does not
survive the downsample from 3840 to 1920.

Neither screenshot needs `.cpc-clip`: at the 950px the panel gives them, `bouncer-rules.png`
(2948×1040) comes out 335px tall and `bouncer-exposure.png` (2948×1676) 540px, both inside the
620px cap. The class is kept for the next capture that does.

`fonts.css` is generated by `build.sh`, which base64-inlines the two woff2 files in `assets/` —
Chrome's `file://` origin rules block them otherwise. It is gitignored; don't edit it.

What a rule is

Reads like
a sentence

This content, for these people, otherwise that. Top to bottom, in that order.

  • In project config, so they deploy with the sections
  • Every rule targeting an element must pass. AND, not OR
  • Adding a rule can only remove access, never grant it
Target
Entries in Members, type Article
Or categories, or a volume, or a URI pattern. Narrowed by Craft's own condition builder.
Access
for Subscribers or Staff
Logged in · groups, any or all · permissions · a shared password · a date window · IP lists.
Response
otherwise render the paywall
Or send to login, redirect, ask for the password, 403, or 404. First denying rule wins.

Protecting files  ·  Pro

The bytes,
not just
the title

The half that is usually skipped, and the reason the plugin exists.

  • Transforms generated outside the public filesystem
  • Range and If-None-Match answered properly. Video seeks
  • Signed, expiring links for somebody with no account
1The URL is rewritten. getUrl() returns the guarded route. No template changes anywhere.
2Every hit is re-checked. The URL ends up in HTML, caches, history and referrers.
3Transforms go to runtime. The volume's transform filesystem is public on most sites.
4Big files hand off. X-Accel-Redirect or X-Sendfile, if the server offers it.
5Or sign a link. HMAC over the asset, transform and expiry. Stateless.

Templates & console

Prove it
before
you ship

Does an anonymous visitor still get the members index? Ask, in the deploy check.

  • audit exits non-zero, so CI can hold the release
  • rules/test answers the question you have on deploy day
  • craft.bouncer.can() gates part of a page, not the page
$ php craft bouncer/rules/test /members/handbook
  anonymous   DENIED   members-only  ·  not logged in
  --user-id=5  ALLOWED   in group Subscribers
$ php craft bouncer/audit
OK       6 rules, all evaluable on this edition
